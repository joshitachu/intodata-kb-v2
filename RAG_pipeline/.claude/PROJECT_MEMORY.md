## Architecture Decisions

| Decision | Choice | Rationale | Date |
|---|---|---|---|
| Parallel tool calls in the runtime tool loop | `ToolAwareLLMResponse.tool_calls` is a LIST (was singular `tool_call`); every provider returns ALL calls from the turn; `agent_loop` answers EVERY call_id with a `role:"tool"` message — executes up to `runtime_tool_max_parallel_calls` (default 5), overflow gets a synthetic `tool_call_budget_exceeded` tool result telling the model to re-issue next turn. | INVARIANT (OpenAI wire contract): every `tool_call_id` in an assistant message MUST be followed by a tool message, or the next request 400s ("tool_call_ids did not have response messages") — so capping must ANSWER overflow calls, never drop them, and `assistant_message.tool_calls` must match the executed+answered set exactly. Kimi k2.5 issues parallel calls routinely (ids are `name:index`). Tool executions run SEQUENTIALLY on purpose: they share one AsyncSession, which cannot run concurrent queries — do not "optimize" with asyncio.gather without per-call sessions. Google/Ollama synthesized ids are index-suffixed (`google_{name}_{i}`) so two parallel calls to the same tool don't collide. | 2026-07-06 |
| Usage dashboard: threads vs doc-generation | `/admin/usage` splits recent activity by data model, not by a single interface value. RAG/chat = `RecentThreadsTable` over `GET /admin/usage/recent-threads` (conversation-backed); doc generation = `DocGenerationTable` over the row-level `GET /admin/usage/recent?interface=doc_generation`. "the rag" means ALL conversation-based interfaces, not just `interface='rag_query'`. | Doc generation is not conversation-backed, so it has no thread rollup and stays a `query_usage` row view via the existing `interface` filter (no new endpoint). INVARIANT for `avg_session_seconds`: a session = one thread's activity on one **UTC** day (`date_trunc('day', created_at)`); length = max−min message time that day; the metric is the AVERAGE of daily spans. Consequences to preserve: a midnight-UTC-crossing session counts as two days, and a single-message day contributes a 0s span (pulls the average down). Any `rag_query`/`deep_dive` usage logged WITHOUT a `conversation_id` will not appear in the thread table. | 2026-07-02 |
| Runtime failure intelligence architecture | Runtime ingestion is source-agnostic and DB-first: `runtime source -> adapter -> central DB -> insight/health APIs -> dashboard/chat`. Adapters may use source-specific mechanics, but the store, APIs, chat tools, and dashboard models stay generic. | Prevents TMC from becoming the product model and lets future runtime sources feed the same central database/server path. User-facing reads must not query the runtime platform directly. | 2026-07-02 |
| Runtime raw-log exposure | Raw logs may be retained internally for parsing and evidence derivation, but dashboard/chat must not expose raw log dumps or quote raw execution log text. User-facing surfaces use sanitized evidence snippets, structured timeline `signal`, incidents, recurrence, freshness, and health rollups. `get_execution_logs` is not in the user-facing chat tool allowlist. | The product workflow is "show me what's broken and why", not raw log browsing. Raw lines can contain secrets/noise and are too low-level for clients/admins. Defensive sanitizer code may still recognize event-like tools for legacy/internal summaries. | 2026-07-02 |
| Talend TMC adapter boundary | TMC endpoint mechanics belong only in `runtime/providers/talend_tmc.py`, TMC tests, source metadata/config, and docs. Current adapter uses reference-repo endpoint families: task execution list/detail, async log request/status/download, paginated log fallback, and observability component metrics; live smoke requires credentials. | Keeps source-specific behavior isolated while mapping into generic runtime executions, failures, log events, and component metrics. No generic DB/schema/API type should be TMC-shaped. | 2026-07-02 |
| Runtime sync scheduler | Scheduler is backend-lifecycle wired but disabled by default. It runs configured adapters on `runtime_sync_interval_seconds` (default 60), avoids overlapping cycles, commits/rolls back per project, logs only source/project/status identifiers, and records adapter failures as sanitized sync status. | Gives the local operational shape without making ingestion mandatory or crashing reads. Enabling requires explicit source/project config and deployed migrations. | 2026-07-02 |
| In-app user guide data-residency wording | `public/guide/index.html` describes AI models as a **configurable provider chain** (cloud default: Voyage embeddings/rerank + cloud LLM; local-only: Ollama) with a data-residency note — it must NEVER claim "no external APIs / all data stays local". | The guide previously asserted fully-local operation, which is false for the default provider chain (Voyage AI, cloud LLM) and is a data-governance misstatement in a client-facing surface. INVARIANT: any deployment-specific "stays local" guarantee must be gated on the actual configuration, not stated absolutely. Consistent with the Embeddings=Voyage decision row below. | 2026-07-02 |
| Runtime failure knowledge = data, not code | All error-code matching, root-cause templates, and next-checks live in `runtime/insights/catalog.py` `FailurePatternCatalog` (Strategy/Registry, module singleton `CATALOG`). parser.py/builder.py delegate via `CATALOG.extract_error_code(message)` and `CATALOG.match(error_code, exception_class, message)`. | Adding a platform/failure family is catalog data + a test with ZERO parser/builder control-flow edits (the no-special-case rule). INVARIANT: numeric/3-digit and the generic `[A-Z]{2,}-\d+` families are anchor-gated (`requires_context` + `context_pattern`) so benign message IDs like `ORD-8842193` never match and poison `primary_error_code` — keep that discipline when adding families. `match` falls back to `generic.unknown` so None is effectively unreachable. | 2026-06-18 |
| Runtime incident signature algorithm | Strong path (error_code OR exception_class present): `sha256(join(non-empty [error_code, exception_class, failed_component]))`. Unknown path (NO diagnostic signal — a bare component is NOT enough): `sha256("unknown|{job}|{component}|{pattern_id}|{sha256(redact(causal_message))[:16]}")`. | Replaced `error_code|exception_class|failed_component` with the `unknown|{job_name}` fallback that collapsed every unknown failure of a job into one false "recurring" group. INVARIANT: distinct unknown failures must get distinct signatures; genuinely identical failures (incl. unknowns) must still collide so recurrence/`test_similar_failures` holds. A signature-algorithm change REQUIRES a rebuild path — `builder.rebuild_runtime_insights(session, project_id=None)` recomputes from the raw store (the source of truth) and is what migration 034 calls. | 2026-06-18 |
| Runtime causal extraction | Parser resolves the deepest `Caused by:` root exception (`_resolve_causal_exception`), NOT `qualified[0]` (the outermost wrapper). Builder selects `primary_error_code`/`failed_component` from the terminal/causal error event (`_select_causal_signal`/`_select_failed_component`), NOT first-seen. | A benign earlier warning was misattributing the cause and poisoning the signature. NB: this supersedes the older "`failed_component` = FIRST error-severity row" invariant from 2026-06-17 — selection is now causal (terminal diagnostic-bearing line), not positional. Exception regex is CamelCase-gated so "IO Error"/bare "Error" never match. `confidence` is now evidence-quality (catalog `specificity` + signal agreement): low = 0 strong signals OR fallback pattern (specificity ≤ 2); high = ≥2 strong AND specificity ≥ 25; else medium. `low` is persisted. | 2026-06-18 |
| Runtime LLM fallback | `runtime/insights/llm_fallback.py` Decorator over the deterministic incident result, gated by `runtime_llm_fallback_enabled` (env `RUNTIME_LLM_FALLBACK_ENABLED`, default OFF). Hooked in `builder._build_incident` ONLY when `confidence == "low"`. Reuses provider-neutral `generation/llm_client.generate_answer`. | Bounded residual escalation that does not reintroduce the EP-006 token bloat. INVARIANT: single call; ≤5 excerpts; ≤300 chars each; 6000-char prompt cap; NEVER raw logs — only already-redacted excerpts + structured signals (every value passes through `redact_credentials` first). Marks `cause_origin="llm_fallback"`, never overwrites high/medium, and FAILS SAFE (LLM error or unparseable output → deterministic result stands, no raise). Flag-off path is byte-for-byte identical to the deterministic path (asserted: client not called). | 2026-06-18 |
| Runtime credential redaction scope | `parser.redact_credentials` now covers BOTH `keyword=value` and inline `user:pass@host`/`user/pass@host` JDBC userinfo (`_USERINFO_RE`); it is the single source of truth, applied before any value is persisted (esp. `endpoint`) or sent to the LLM. Severity goes through `builder.normalize_severity` (error/severe/fatal/critical→error, warn/warning→warning) at every callsite. | Inline JDBC URLs were leaking credentials into the surfaced `endpoint` field; severity was matched literally and missed SEVERE/FATAL/uppercase. Fixed once at the shared-helper level so every path is covered — do not reimplement either helper. | 2026-06-18 |
| EP-006 `useRuntimeIncidents` — future use | `useRuntimeIncidents` (with `IncidentFilters.projectId`) is implemented in `hooks/useRuntimeLogs.ts` but has no call site in the logs page. Add a call site when an incidents list tab or panel is built. | 2026-06-17 |
| EP-006 client provider method guard | `execute_runtime_tool` uses `getattr(provider, tool_name, None)` + callable check before invoking any method. Mock and talend_tmc intentionally do NOT implement the 3 insight tool methods (`analyze_execution_failure`, `get_execution_timeline`, `get_runtime_incident`); this is acceptable per plan; add implementations when mock insight fixtures are needed. | 2026-06-17 |
| EP-006 `_EVENT_LIKE_TOOLS` and timeline summary skip | `_EVENT_LIKE_TOOLS = frozenset({"get_execution_logs", "get_execution_timeline"})` marks tools whose results are timestamped event lists. `build_runtime_tool_summary` skips ALL records from these tools (they carry no `execution_id` field and must never have message text in the summary). A `get_execution_timeline` call will always produce ZERO summary entries — this is intentional, not a bug. The frozenset makes the design explicit. | 2026-06-17 |
| EP-006 `get_runtime_incident` dedup key limitation | `build_runtime_tool_summary` uses `(tool_name, execution_id)` as the dedup key for `get_runtime_incident` results (execution_id extracted from the nested incident sub-dict). The current 1:1 execution→incident invariant makes this safe. The semantically precise key would be `(tool_name, incident_id)`. If the invariant is ever relaxed, a second distinct incident for the same execution would be silently dropped — harden then by changing to `(tool_name, incident_id or execution_id)`. | 2026-06-17 |
| EP-006 `failed_component` invariant | `failed_component` in `RuntimeExecutionSummaryRow` is always the component from the FIRST error-severity log row (the originating component), never the last. The last ERROR row is typically a parent route propagation (e.g. `[esb_order_sync_route] Route failed: ...`). Builder iterates forward, not reversed. | 2026-06-17 |
| EP-006 timeline existence-gate design | `get_execution_timeline()` gates on `RuntimeExecutionRow` (not `RuntimeExecutionSummaryRow`). This is intentional: a summary row is absent when insights have not been built yet, but the raw execution exists. Gating on the execution row means an in-scope execution without built insights returns 200+empty list, not 404. The 404 case is reserved for unknown or out-of-scope execution_ids. | 2026-06-17 |
| EP-006 two-query join pattern | Insight repository methods never use SQLAlchemy ORM joins. Instead: (1) query the primary table with scope filter, (2) extract an id set from results, (3) batch load the secondary table with `.in_(ids)`, (4) merge via `{id: row}` dict in Python. Reasons: avoids join complexity across store/insight table boundary, stays SQLite-compatible for tests, and does not require ORM relationship declarations on models that span sub-system boundaries. | 2026-06-17 |

## Lessons Learned / Gotchas

- The declarative `Base` (`src/db/base.py`) auto-declares `created_at` AND `updated_at` on EVERY model. So any migration that `create_table`s a new model-backed table MUST include both columns (`TIMESTAMPTZ NOT NULL`, `server_default=sa.func.now()`) — otherwise every SELECT on that table 500s with `asyncpg UndefinedColumnError: column <table>.created_at does not exist`. This bit `runtime_component_metrics`, `runtime_artifacts`, `runtime_connections`, `runtime_job_dependencies` (migrations 037/043 omitted them; fixed in 048). When adding a table or reviewing a create_table migration, cross-check the two `Base` timestamp columns are present.

- `tests/test_generation/test_conversational_rag.py` has FLAKY pre-existing failures (oscillates 3↔5 failed across identical runs, seen 2026-07-06): `TestRetrievalLadder`/`TestLadderEntityMatching` tests die with `AttributeError: 'coroutine' object has no attribute 'id'` at `src/retrieval/metadata_retriever.py:119` — the AsyncMock db plumbing returns a coroutine from `fetchone()` when the metadata-classifier path is hit. Do not attribute these to an unrelated diff; verify against baseline (`git stash`) before debugging.

- PostgreSQL `JSONB` → generic `JSON` for SQLite test compat (still works as JSONB on Postgres)
- SQLAlchemy does not reliably persist in-place JSONB list/dict mutations; assign the updated value and call `flag_modified(model, "column")` or use a mutable extension. This matters for marking backup codes as used.
- Refresh JWTs need a nonce/`jti`; `sub` + `type` + second-resolution `exp` can produce identical tokens during rapid repeated logins and collide on the stored token hash.
- SQLite needs `PRAGMA foreign_keys=ON` for CASCADE tests — added to conftest.py
- SQLAlchemy needs `passive_deletes=True` on parent relationship for DB-level CASCADE to work
- `setuptools.backends._legacy:_Backend` doesn't exist on Python 3.14 — use `setuptools.build_meta`
- Python 3.14 is installed on this machine (not 3.11)
- Zod `.default()` doesn't make field optional in `z.infer` — use `.optional().default()` + `z.input` for request types
- OneDrive paths can cause build issues — delete `.next` cache if build fails with manifest errors
- Qdrant requires explicit `create_payload_index()` on any field used in `FieldCondition` filters — just creating the collection is not enough
- `create_payload_index()` is idempotent — safe to call on every startup without checking if index exists
- `nomic-embed-text` cosine similarity for natural language queries against relevant chunks: typically 0.2-0.5. Threshold must be ≤0.2 to avoid dropping borderline-relevant results
- Changing chunk size requires re-ingestion of all existing documents
- Always use `res.text()` + `try { JSON.parse(...) } catch {}` for error responses — never assume error bodies are valid JSON (Next.js can return HTML error pages from webpack crashes)
- `fastapiFetch` must check `res.status === 204` before calling `res.json()` — DELETE endpoints return empty bodies
- When mocking `AsyncSession.execute()` for `select()` queries, the mock must return a sync `MagicMock` (not `AsyncMock`) for `.scalars().first()` chain since `execute()` is already awaited
- Map-reduce: use `Semaphore(3)` for parallel LLM calls to avoid overwhelming local Ollama
- `fastembed` requires Rust toolchain (py-rust-stemmers) — use sklearn TF-IDF as fallback for sparse embeddings
- Qdrant `query_points()` with named vectors: use `query=embedding, using="dense"` (not `query=NamedVector(...)`)
- Qdrant hybrid search: use `Prefetch` with `query=raw_vector, using="dense"` and `query=SparseVector(...), using="sparse"`, then `query=FusionQuery(fusion="rrf")`
- When adding feature flags that change dispatch paths (e.g., `search_multi_query` vs `search_similar`), existing tests need settings mocks to disable new features
- Cross-encoder models are lazy-loaded singletons (~80MB download on first use); mock `_get_model()` in tests
- Provider registry must resolve functions at call time (not at import time) for `unittest.mock.patch()` to work — use string-based registry + `getattr(sys.modules[__name__], func_name)`
- Semantic chunker: single-paragraph texts that fit in one chunk should bypass min_tokens filter (otherwise empty returns for short documents)
- Python 3.14 has limited package compatibility — many packages don't have pre-built wheels yet
- **Next.js `output: "standalone"` evaluates `next.config.ts` at `npm run build` time** — `process.env.*` read from inside `rewrites()` template literals is baked into the routes manifest, not resolved per-request. For env-driven proxy targets (e.g. `KB_API_URL` → `/mcp/*` rewrite), pass the value as a Docker build ARG, not a runtime env var. Symptom: runtime env reaches the container but the rewrite still uses the compile-time fallback — produces `ECONNREFUSED ::1:<port>` on proxied routes.
- **Mandatory MFA is enforced server-side, not just by the frontend guard** — any new authenticated protected route that uses `CurrentUser`, `AdminUser`, or permission dependencies inherits the enrollment gate automatically. Only add to `MFA_ENROLLMENT_EXEMPT_PATHS` for endpoints needed to render/complete MFA enrollment or maintain/logout the session.
- **Onboarding source upload is post-wizard by design** — users declare their stack at onboarding (platform-select) and upload ZIPs whenever ready from `/settings/sources`. Upload state is derived: `selected_platforms` (from `user_onboarding`) ∩ `projects.platform` (from MCP). No separate `uploaded_platforms` table — avoid adding one; the join is the source of truth.
- **Qdrant Cloud uses port 443, not 6333**: `qdrant-client` defaults to port 6333 for REST connections. Qdrant Cloud exposes API on 443 (standard HTTPS). Always use `https://...cloud.qdrant.io:443` in the URL — without `:443`, the client tries port 6333 and fails with `All connection attempts failed`
- **TF-IDF sparse embeddings are broken for hybrid search**: `TfidfVectorizer` fitted per-call creates different vocabulary mappings between ingestion and query time. Index 0 means different words in different calls. Use hash-based approach: `hash(token) % DIM` for deterministic, stateless sparse vectors.
- **JSON null vs missing key**: `dict.get("key", "default")` returns `None` (not `"default"`) when key exists but has value `null`. Use `(dict.get("key") or "default")` to handle both missing and null.
- **Lazy imports break `unittest.mock.patch`**: When a function is imported inside another function body (`from module import func`), `patch("caller_module.func")` fails with `AttributeError`. Must patch at the definition site: `patch("definition_module.func")`.
- **Embedding provider chain**: Same pattern as LLM provider chain. Voyage AI uses OpenAI-compatible API format — reuse the `openai` SDK with different `base_url`.
- **Kimi K2.5 instant mode temperature**: When thinking is disabled (`extra_body={"thinking": {"type": "disabled"}}`), Kimi K2.5 enforces exactly `temperature=0.6`. Any other value returns HTTP 400: `invalid temperature: only 0.6 is allowed for this model`.
- **OpenAI SDK `max_retries=0` for provider chains**: The `AsyncOpenAI` client defaults to `max_retries=2` with exponential backoff. When using a multi-provider fallback chain, set `max_retries=0` — otherwise the SDK silently burns 10+ seconds retrying a failed call before the outer fallback logic can switch to the next provider.
- **Intent classifier is pure overhead**: Qdrant search is ~50ms. "Skipping search for chitchat" saves 50ms but costs 3-12s for the LLM call. The `NO_RESULTS_PROMPT` handles greetings/chitchat naturally when search returns 0 results. Always route through search.
- **Voyage AI `dimensions` param not supported**: `voyage-4-large` always returns 1024-dim natively. Passing `dimensions=` causes HTTP 400. Don't use the `dimensions` parameter with Voyage API.
- **Reranker min-score is essential**: Without a minimum score threshold, the reranker returns top_k candidates regardless of relevance. Chitchat queries get irrelevant chunks (score -9.13) sent to LLM. Use `reranker_min_score=0.0` to filter negative scores.
- **Hindsight must be added to ALL query paths**: Three separate query paths exist — `rag_chain.py` (/query), `query.py` (/query/stream), `conversational_rag.py` (conversations). Each needs its own recall+retain integration. Forgetting one means that endpoint silently skips memory. The pattern is always: `ensure_banks → recall → build_memory_context → inject into messages → retain after answer`.
- **Pre-load ML models at startup**: Cross-encoder model downloads ~80MB on first use. Lazy loading means the first user request takes +100s. Call `warmup()` in the lifespan handler.
- **Qdrant dimension mismatch on provider switch**: When changing embedding provider (e.g. Ollama 768-dim → Voyage AI 1024-dim), the existing Qdrant collection has the old dimension. `ensure_collection()` auto-detects this and recreates. All documents must be re-ingested after recreation.
- **NO_RESULTS_PROMPT vs memory injection**: When injecting memory context as a follow-up system message, the main system prompt must explicitly declare that memory context is trusted information. Otherwise, "NEVER make up information or answer from general knowledge" causes the LLM to ignore the injected memories (it treats them as "general knowledge" it should not use).
- **Cross-encoder domain mismatch**: MS MARCO-trained cross-encoders (e.g. `ms-marco-MiniLM-L-12-v2`) return negative scores for technical/enterprise documents — they're trained on web search relevance, not domain-specific content. When `min_score=0.0`, ALL candidates get filtered out and nothing reaches the LLM. Use a domain-agnostic reranker (e.g. Voyage AI `rerank-2.5`) that returns calibrated 0-1 scores.
- **Reranker should be the sole quality gate**: When using a reranker, set the pre-filter (RRF/vector search) threshold to 0.0 so all candidates reach the reranker. The reranker's min_score is the quality gate, not the vector search threshold. Double-filtering drops too many candidates.
- **subprocess stderr deadlock on Windows**: When using `subprocess.Popen` with both `stdout=PIPE` and `stderr=PIPE`, reading stdout first and stderr after can deadlock if stderr's pipe buffer fills (~4KB on Windows). Always drain stderr concurrently using `asyncio.create_task()` (or `asyncio.gather`). See `claude_service.py` and `deep_dive_service.py` for the pattern.
- **Claude CLI `stream-json` text delivery**: Claude CLI may not emit `content_block_delta` events (or may batch them due to Windows pipe buffering). Always handle text from both `content_block_delta` (preferred, incremental) AND `assistant` events (fallback, full turn). Use a `_text_streamed_via_delta` flag to avoid duplication.

- **`backdrop-filter: blur` is one of the most expensive CSS properties** — never use it on per-node or per-group elements in graph views. Even `blur(1px)` forces the GPU to re-blur whatever is behind every element on every paint. For ~10 elements this is a constant frame-rate killer; the visual effect at 1px is also imperceptible. Use a flat gradient or a colored border instead.
- **Infinite CSS animations (`animation: ... infinite`) cause constant repaint loops** — even when the user is idle, the GPU keeps painting every frame. In ReactFlow specifically, dashed/animated edge styles like `.react-flow__edge.animated path { animation: edge-flow ... infinite }` paint forever for every dashed edge in the visible graph. Either remove the infinite animation entirely or scope it to a JS-set `data-animated` attribute opt-in.
- **Per-node mount animation re-fires on every layout change in ReactFlow** — if a CSS class like `.topo-node-enter { animation: node-enter 0.3s }` is applied via `className` on each node component, every direction/compact/expand-collapse toggle remounts nodes and the keyframe re-runs across the entire visible graph at once, producing a visible "wash" of animation. Don't put per-instance entry animations on graph nodes.
- **ReactFlow's `setNodes` reconciles every node** — guard hover/search effects with a `useRef` that early-outs when the new state matches the previous (`prevHoverRef.current`, `prevSearchRef.current`). Without this, any unrelated re-render that re-enters the same hover state still rewrites every node object, triggers full reconciliation, and produces visible "ripple lag" on large graphs. Pattern: `if (state === prevRef.current) return; prevRef.current = state;` at the top of the effect.
- **`setNodes((nds) => nds.map(...))` MUST return same-reference nodes for unchanged ones** — the early-out alone is not enough. Even when we *do* run the effect (because the hovered node actually changed), the inner `map` still rewrites every node ref by default. With `React.memo` on the node components, returning the same node reference (or at least the same `data` reference) for nodes whose dimming/highlight state didn't actually change makes the per-component render skip. Pattern: `if (n.data.dimmed === newDimmed && n.data.highlighted === newHighlighted) return n;` before the `{ ...n, data: { ... } }` spread. Same idea for `setEdges` against `e.style?.opacity`. On a graph with 80+ nodes this is the difference between "ripple lag on every hover" and "instant". Use the destructuring trick `const { opacity: _drop, ...restStyle } = e.style ?? {}` to *remove* a key rather than set it to `undefined` (the latter still produces a new style object).
- **MiniMap re-renders all nodes on every viewport movement** — gate it on a node-count threshold (e.g. `visibleNodes.length <= 150 || isCollapsed`). On heavy graphs the minimap is both expensive and useless because every node is a pinhead.
- **Inline `transition: opacity 0.3s ease` is dangerous combined with hover dimming** — when hover dimming rewrites the entire node array, every node has to animate its opacity for 0.3s simultaneously, which is the visible "ripple lag". For graph views prefer instant dimming (no transition); the snappy feel beats the visual polish.
- **Same-reference dimming optimization is undone by the layout effect unless laid-out nodes carry explicit `dimmed: false, highlighted: false` defaults** — `setNodes([...bgNodes, ...laid])` writes nodes whose `data.dimmed` is `undefined`. The hover effect's same-reference fast path is `if (n.data.dimmed === !isMatch && n.data.highlighted === isMatch) return n;` — `undefined !== false` strict-equality fails for every freshly-laid node, so the entire graph gets rewritten on the FIRST hover after any layout change. Initialize the defaults: `laid.map((n) => ({ ...n, data: { ...n.data, dimmed: false, highlighted: false } }))` before calling `setNodes`. After the first hover all nodes have explicit `false`/`true` and subsequent hovers are fast — which is exactly what made round 3 of the topology perf pass invisible to most projects but lethal on `scherpenhuizen-talend`.
- **ReactFlow `fitView` animations stack when fired from multiple effects on the same frame and dominate frame time on heavy graphs** — the layout `useEffect` calls `fitView({duration: 300})` and the search `useEffect` calls `fitView({duration: 400})`; both can fire when `groupMembership` rebuilds with the same shape or when the user types fast. Gate them with a "last-fit-key" `useRef` keyed on the meaningful layout identity (`${selectedProject}|${direction}|${compactMode}|${nodeCount}`) and only call `fitView` when the key actually changed. Reset the ref on project switch so the new project still gets its initial fit.
- **Search auto-fit must not run on every keystroke when the match set is large** — typing one letter in a project that matches 40 nodes triggers a 400ms `fitView` zoom-fit across the entire viewport, and the animation stacks with subsequent keystrokes. Cap on `searchMatchIds.size <= 8` so single-letter searches just dim the rest; once the user has typed enough that the match shrinks to a useful size, the auto-fit kicks in. This matches every other code-search UI.
- **JWT cookie auth across services**: RAG backend (port 8000) issues cookies. Next.js (port 3000) proxies auth endpoints and forwards cookies to FastAPI. MCP server (port 8002) validates JWT independently using shared `JWT_SECRET_KEY`. Dashboard (port 8001/nginx) forwards cookies via `proxy_set_header Cookie`. All services must share the same JWT_SECRET_KEY.
- **Refresh token cookie path**: Refresh token cookie path is `/api/v1/auth/refresh` — browser only sends it to that endpoint. Access token cookie path is `/` — sent on every request.
- **Default admin password**: Set via `ADMIN_DEFAULT_PASSWORD` env var (default: "admin"). The lifespan handler seeds the admin user on first boot and also back-fills the password hash for existing admin users that were created before auth was added.

### Retrieval ladder (Slice 4, 2026-06-12)

- **The ladder lives only in the conversational QA search path** (`_prepare_rag_context`, after previous-source reuse, before no-results). METADATA/RESPOND/SUMMARY intents and the non-conversation `/query` path never descend to internal layers. Rung 2 must always pass explicit `source_layers` to `search_layered()` — never `None` (that re-enables the legacy is-empty tolerance and would leak the default partition into a layer-scoped search).
- **Rung-1 answers are generated inside `_prepare_rag_context` under the [NEED_SEARCH] contract** (`build_conversational_messages(context_first=True)`). Consequences to remember: the `images` vision parameter must be threaded into every `generate_answer` call added there (inspection caught a silent vision drop once already), and fresh QA answers stream as a single SSE token by design.
- **DocGapEvent is written only when rung 2 actually supplies an answer** — clean refusals are not gaps. The event's purpose is repeated-omission analysis per project; do not start logging refusals or rung-1 successes into it.
- **`friendly_display_name()` in `retrieval/search.py` is the single place internal filenames become human-readable.** Raw `{project}/_internal/...` paths must never reach chat citations or LLM context headers; context builders use `display_name or legacy-format(filename)` for stored legacy sources.
- **`merge_sources_by_document` must propagate every new Source field** — forgetting it silently nulls metadata on DocumentSource (bit us with `run_id`/`project_id` in this slice; the doc-gap event then loses its run linkage).

### Document roles (2026-06-25)

- **`document_role` is independent from `source_layer`**: `source_layer` partitions generated/internal artifact layers; `document_role` describes how an uploaded document may be used in answers. Keep both filters additive with RBAC/project filters, never substitutive.
- **Missing or blank `document_role` means `source`** for backwards compatibility. This is intentional for legacy chunks and generated knowledge-base markdown pushed through `/ingest/md`, so they remain project evidence unless a caller explicitly tags them otherwise.
- **Only `source` is project evidence.** `reference`, `guidance`, `standard`, and `policy` may shape interpretation, terminology, constraints, or compliance checks, but they cannot prove project-specific facts. `template` is structure-only and is retrieved only when `has_template_intent(query)` is true.
- **Role-aware query parity matters**: conversational QA, `/query`, and `/query/stream` should all use the same source-first + auxiliary/template context contract. If adding a new query entry point, do not call the old flat search path for QA without role splitting.
