You are analyzing a Talend integration project to build an **Expression Catalog** — a comprehensive index of every expression, transformation, filter, and code snippet in the project, with plain-English explanations and complexity scores.

## Talend Expression Context

Expressions in Talend appear in several places:

### 1. tMap Column Expressions (entries)
These define how target columns are derived from source columns:
- **Direct field map**: `row1.CustomerName` — copies source column as-is
- **Function call**: `StringHandling.TRIM(row1.Name)` — applies a Talend built-in function
- **Chained functions**: `StringHandling.UPCASE(StringHandling.TRIM(row1.Name))` — multiple transformations
- **Ternary/conditional**: `row1.Status.equals("A") ? "Active" : "Inactive"` — conditional logic
- **Date operations**: `TalendDate.parseDate("yyyy-MM-dd", row1.DateStr)` — date parsing/formatting
- **Null handling**: `row1.Value != null ? row1.Value : 0` — null coalescing
- **String concatenation**: `row1.FirstName + " " + row1.LastName` — combining fields
- **Type casting**: `Integer.parseInt(row1.Code)` — type conversion
- **Lookup reference**: `row2.LookupValue` — value from a joined lookup table

### 2. tMap Variable Expressions (var_entries)
Intermediate calculations stored in tMap variables. These are often used by other expressions:
- `var.fullName = row1.FirstName + " " + row1.LastName`
- `var.isActive = row1.Status.equals("A")`

### 3. tMap Filter Expressions
Row-level filters that determine which rows pass through:
- `row1.IsDeleted == 0`
- `row1.OrderDate.after(TalendDate.parseDate("yyyy-MM-dd", "2020-01-01"))`

### 4. tFilterRow Conditions
Component-level filters with explicit condition configuration.

### 5. SQL Expressions
In source query components (tMSSqlInput, etc.):
- WHERE clauses with business logic
- CASE statements for conditional transformations
- SQL functions (ISNULL, CONVERT, DATEPART, etc.)

### 6. Java Code (tJava, tJavaRow, tJavaFlex)
Inline Java code that implements custom logic:
- Validation rules
- Complex calculations
- External API calls
- Global variable manipulation

### 7. Routine Code
Custom Java methods in routines referenced by jobs.

## Complexity Scoring

Score each expression 1-5:
- **1 (trivial)**: Direct field map (`row1.col`), constant (`"value"`), simple null check
- **2 (simple)**: Single function call (`StringHandling.TRIM(row1.col)`), basic type cast
- **3 (moderate)**: Chained functions, ternary with function calls, lookup joins with conditions
- **4 (complex)**: Nested ternaries, multi-step calculations, SQL CASE with 3+ branches, date arithmetic
- **5 (very complex)**: Multi-line Java code, complex SQL subqueries, regex operations, external API calls

## Expression Type Classification

Classify each expression:
- `field_map`: Direct column reference (`row1.col`)
- `filter`: Row filtering condition
- `lookup`: Value from a lookup/join table
- `ternary`: Conditional expression (? :)
- `function_call`: Talend/Java function application
- `sql_fragment`: SQL expression (WHERE, CASE, etc.)
- `java_code`: Inline Java code (tJava/tJavaRow)

## Business Rule Flagging

Flag an expression as `is_business_rule: true` when it:
- Encodes a business decision (status code mapping, date cutoffs, threshold values)
- Implements a data quality rule (validation, standardization)
- Contains hardcoded business parameters (fiscal year, category codes)
- Filters data based on business criteria (not just technical null checks)

Do NOT flag as business rule:
- Technical null handling without business meaning
- Simple type conversions
- Direct field mappings
- Standard formatting (trim whitespace)
