You are analyzing a Talend integration project. Your task is to produce a **Data Flow Analysis** — a complete mapping of every data input, transformation, and output for each job in this chunk, with human-readable explanations of all transformation logic.

## Talend Context
In Talend, data flows through components via typed connections:
- **Source components** (tMSSqlInput, tBigQueryInput, tFileInputDelimited, tRESTClient, etc.) read data from external systems. They may contain SQL queries, file paths, or API endpoints. The schema defines the columns and data types being read.
- **tMap**: The primary transformation component. It contains:
  - **Input tables**: One or more incoming data flows (main + lookup tables)
  - **Output tables**: One or more outgoing data flows
  - **Expressions**: Java-based expressions that transform, filter, combine, or derive column values. These use syntax like `row1.column_name`, `Var.variable`, `StringHandling.TRIM()`, `TalendDate.parseDate()`, etc.
  - **Filters**: Row-level filter expressions that determine which rows pass through to an output table
  - **Join conditions**: For lookup tables, the join key expressions and join model (inner join, left outer join, unique/first match, all matches)
  - **Reject links**: Rows that fail a lookup join can be routed to a reject output
- **tJavaRow / tJava**: Custom Java code that transforms data row-by-row or in bulk
- **tAggregateRow**: Groups and aggregates data (SUM, COUNT, AVG, etc.)
- **tFilterRow**: Filters rows based on conditions
- **tSortRow**: Sorts data by specified columns
- **tUnite / tDenormalize / tNormalize**: Structural transformations
- **Sink components** (tMSSqlOutput, tBigQueryOutput, tFileOutputDelimited, etc.) write data to external systems. They specify write mode: INSERT, UPDATE, INSERT_OR_UPDATE, DELETE, BULK_INSERT.
- **Schema propagation**: Each connection carries a schema (column name, type, length, nullable). Schemas can be defined inline or referenced from REPOSITORY metadata.

## What to Extract
For each job in this chunk:

1. **DataInputs**: For every source component, identify:
   - Source system name and type (MSSQL, BigQuery, file, API, etc.)
   - Database/schema/table or view name, or file path
   - The SQL query if present (include the full query text)
   - Schema: list all columns with their data types
   - Any filtering in the query (WHERE clauses)
   - Connection/context variable references used for the connection

2. **Transformations**: For every tMap and transformation component:
   - List every output column and its expression
   - **CRITICAL**: For each expression, provide a HUMAN-READABLE explanation of what it does. Do not just repeat the expression — translate it to plain English. Examples:
     - `StringHandling.TRIM(row1.CustomerName)` -> "Removes leading and trailing whitespace from the customer name"
     - `row1.Amount != null ? row1.Amount : 0` -> "Uses the amount value if present, otherwise defaults to zero"
     - `TalendDate.formatDate("yyyy-MM-dd", row1.CreatedDate)` -> "Formats the creation date as YYYY-MM-DD string"
     - `row1.Status.equals("A") ? "Active" : "Inactive"` -> "Converts status code 'A' to 'Active', all other codes to 'Inactive'"
   - Identify lookup joins: which tables are joined, on what keys, join type, and what happens to non-matching rows
   - Identify filter expressions and what rows they exclude
   - Identify any data type conversions happening

3. **DataOutputs**: For every sink component, identify:
   - Target system name and type
   - Database/schema/table name, or file path
   - Write mode (INSERT, UPDATE, UPSERT, DELETE, BULK)
   - Which columns are written and their mapping from upstream
   - Any ON CONFLICT or key columns for updates

4. **Data lineage**: For key columns, trace the path from source to target through all transformations.
