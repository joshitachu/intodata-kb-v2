You are analyzing a Talend integration project. Your task is to produce an **External Systems Catalog** — a comprehensive inventory of every external system, service, database, file system, and API that the jobs in this chunk connect to, along with connection details, usage patterns, and a topology diagram.

## Talend Context
Talend jobs interact with external systems through specialized connector components:
- **Database connectors**: tMSSqlInput/Output/Connection, tOracleInput/Output, tMySqlInput/Output, tBigQueryInput/Output/Connection, tPostgresqlInput/Output, etc. These reference connection metadata (host, port, database, schema, credentials) either inline (BUILT_IN) or from shared metadata (REPOSITORY).
- **File connectors**: tFileInputDelimited, tFileOutputDelimited, tFileInputExcel, tFileOutputExcel, tFileList, tFileDelete, tFileCopy. These read/write from local or network file paths.
- **Cloud storage**: tS3Input/Output, tAzureBlobInput/Output, tGoogleStorageInput/Output. Cloud object storage connectors.
- **API connectors**: tRESTClient, tSOAP, tHTTPRequest. HTTP-based service integrations.
- **Message queues**: tKafkaInput/Output, tActiveMQInput/Output, tJMSInput/Output.
- **SFTP/FTP**: tFTPGet, tFTPPut, tSFTP. File transfer protocol connectors.
- **Email**: tSendMail, tPOP3. Email sending/receiving components.
- **Metadata connections**: Defined in the Talend repository under `metadata/connections/`, these are reusable connection configurations referenced by multiple jobs. They contain host, port, database, schema, username, and (encrypted) password.
- **Connection components**: tMSSqlConnection, tBigQueryConnection, etc. — these open a persistent connection at the start of a job, and subsequent Input/Output components in the same job reuse it via "Use existing connection" setting.

## What to Extract

1. **External system inventory**: For every external system detected, provide:
   - System name (derived from metadata connection name or component configuration)
   - System type (MSSQL, BigQuery, SFTP, REST API, local filesystem, etc.)
   - Connection details: host/endpoint, port, database/dataset name, schema
   - Authentication method: username/password, service account, API key, certificate, anonymous
   - Which context variables are used for connection parameters
   - Whether the connection is REPOSITORY-based (shared) or BUILT_IN (per-component)

2. **Usage mapping**: For each external system:
   - Which jobs connect to it
   - What operations are performed (READ, WRITE, READ_WRITE, DELETE)
   - Which specific tables/views/endpoints are accessed
   - Estimated data volume indicators (if queries contain LIMIT, TOP, or date filters)

3. **Criticality rating**: Rate each external system:
   - **CRITICAL**: Production databases written to, systems where data loss would be severe
   - **HIGH**: Production databases read from, systems feeding downstream processes
   - **MEDIUM**: Staging/temporary storage, logging systems
   - **LOW**: Development/test systems, optional integrations
   - Explain the rationale for each rating

4. **Connection patterns**:
   - Which jobs open their own connections vs. use connections opened by parent jobs?
   - Are there connection pools or shared connections across subjobs?
   - Are connections properly closed (look for tMSSqlClose, tBigQueryClose, etc. in tPostJob)?

5. **Network topology**: Identify the network flow:
   - Source systems (data originates here)
   - Intermediate systems (staging, temp storage)
   - Target systems (final destination)
   - Direction of data flow between systems

6. **Security observations**:
   - Systems using plaintext credentials vs. encrypted
   - Systems accessible without authentication
   - Systems using hardcoded IPs vs. DNS names
   - Any VPN/tunnel indicators in connection strings
