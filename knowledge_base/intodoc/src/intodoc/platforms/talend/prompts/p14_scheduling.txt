You are analyzing a Talend integration project. Your task is to produce a **Scheduling & SLA Analysis** — infer the scheduling patterns, orchestration chains, job dependencies, execution frequency, critical paths, and SLA requirements based on job structure, tRunJob chains, context variables, and naming patterns.

## Talend Context
Talend .item files do not contain built-in scheduling metadata — scheduling is typically managed externally (cron, Task Scheduler, enterprise schedulers like Control-M, Airflow, etc.). However, you can infer scheduling and SLA requirements from:
- **tRunJob chains**: Parent jobs that call child jobs in sequence reveal the execution order and dependencies. The depth of the chain (how many levels of nesting) indicates complexity and potential execution time.
- **Job naming patterns**: Layer codes (RAW, CLEAN, PUBLISH) suggest a sequential pipeline. Region codes suggest parallel execution across regions.
- **Context variables**: Parameters like `StartDate`, `EndDate`, `BatchID`, `RunDate` suggest that jobs are scheduled with date-based parameters (nightly, monthly, etc.).
- **tPreJob/tPostJob**: Components that execute before/after the main job (e.g., tPreJob sends an email notification, tPostJob updates a control table) indicate orchestration and monitoring requirements.
- **Global/Master jobs**: Jobs named "Global" or "Master" or "Orchestrator" typically orchestrate multiple regional or domain-specific jobs.
- **tRunIf conditions**: Conditional job execution based on context variables or runtime checks (e.g., `context.RunMode.equals("FULL")`) indicates different execution modes (full refresh vs incremental, production vs test).
- **tWaitForFile/tFileExist**: Jobs that wait for files to arrive suggest event-driven or batch-driven scheduling.
- **Database control tables**: Jobs that read/write to control tables (execution logs, batch status, last run timestamps) indicate tracking and dependency management.

## What to Extract

1. **Job scheduling inference**: For each job:
   - Estimated execution frequency (nightly, hourly, weekly, monthly, on-demand, event-driven)
   - Evidence for the frequency estimate (context variable names, job name patterns, data volume hints)
   - Is it a standalone job or part of a chain?
   - Is it triggered by a parent job or scheduled independently?

2. **Job dependency chains**: For each tRunJob relationship:
   - Parent job name
   - Child job name(s) called (in order)
   - Chain depth (how many levels of nesting)
   - Execution mode (sequential, parallel via onComponentOk triggers, conditional)
   - Estimated total execution time for the chain

3. **Critical path analysis**: Identify the longest job chains and the jobs that are bottlenecks:
   - Which job chain has the most steps?
   - Which jobs take the longest to run (inferred from data volume, complexity, heavy transformations)?
   - Which jobs are on the critical path for SLA delivery (e.g., must complete by 6 AM for morning reports)?

4. **Bottleneck identification**: Identify jobs that are likely performance bottlenecks:
   - Jobs with large data volumes (millions of rows)
   - Jobs with heavy transformations (complex tMap logic, multiple lookup joins, aggregations, sorts)
   - Jobs with external system dependencies (slow APIs, remote databases)
   - Jobs that run serially when they could run in parallel

5. **SLA recommendations**: For each job or job chain, recommend:
   - Expected execution time (inferred from complexity and data volume)
   - Recommended SLA window (e.g., "must complete within 2 hours")
   - Monitoring points (where to check for failures or delays)
   - Escalation triggers (when to alert if SLA is at risk)

6. **Orchestration patterns**: Identify common patterns:
   - RAW -> CLEAN -> PUBLISH pipeline
   - Regional fan-out: Global job calls BRA, ITA, JPN, SAF, USA jobs in parallel
   - Domain-specific pipelines: separate chains for Sales, Finance, HR, etc.
   - Error recovery patterns: retry logic, fallback jobs, manual intervention triggers

7. **Dependency diagram**: Generate a Mermaid diagram showing the full job dependency graph (parent -> child relationships).
