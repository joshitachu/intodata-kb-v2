You are analyzing a Workato integration project. Your task is to produce a **Column-Level Lineage Matrix** -- trace every field from its source trigger output through datapill transformations to its final destination, documenting exactly what happens to the data at each step.

## Workato Context
In Workato, column-level lineage is encoded in datapill references and formula expressions:

### Trigger Output -> Action Input Flow
1. **Trigger output** (step 0) defines the initial field schema -- what data enters the recipe from the source system (Salesforce record fields, webhook payload, database query columns, event topic payload, API request body).
2. **Datapill references** in action inputs map trigger/step outputs to action inputs. Each input field on an action step contains either a static value, a datapill reference, or a formula expression.
3. **TMapEntry data from the parser** (when available) provides structured field-level mapping:
   - `table_name` = step alias (the action step receiving the data)
   - `column_name` = the destination field name
   - `expression` = the datapill formula that computes the value
4. **Target actions** (create_record, update_record, upsert_record, run_sql, etc.) define where the data lands in the destination system.

### Datapill Reference Syntax
- **Old format**: `#{_('data.step_alias.field_path')}` -- references a field from a previous step's output
- **New format**: `{{steps.step_alias.field_path}}` or `{{trigger.field_name}}` -- handlebars-style references
- **Nested fields**: `#{_('data.salesforce_1.billing_address.city')}` -- dot notation for nested objects
- **Array indexing**: `#{_('data.foreach_1.current_item.field')}` -- inside foreach loops, references current item

### Transformation Types
- **Direct datapill map**: `#{_('data.trigger.customer_name')}` -- field passes through unchanged
- **Formula method chain**: `#{_('data.trigger.customer_name')}.strip.upcase` -- transformations applied
- **Ternary conditional**: `#{_('data.trigger.status')}.present? ? #{_('data.trigger.status')} : 'UNKNOWN'`
- **Constant**: `'US'` or `42` -- hardcoded value, no source field
- **String interpolation**: `"Order #{_('data.trigger.order_id')} - #{_('data.trigger.customer_name')}"` -- combining multiple datapills
- **Lookup enrichment**: Value sourced from a lookup_table_entry action output -- adds columns from reference data
- **Cross-recipe**: Values passed via call_recipe / recipe function parameters or event topic payloads

### Default Type Conversions
Workato auto-converts between compatible types (string <-> number, string <-> date) based on the target field's expected type. These implicit conversions can cause subtle data changes (precision loss, format changes) that are invisible in the recipe editor.

## What to Extract

For every field that flows through this chunk's recipes:

1. **Source**: `source_system.source_object.source_field` -- where the data originates (trigger output, API response, search results)
2. **Transformations**: Each step that modifies the data:
   - `transformation_type`: "direct_map", "formula_chain", "ternary", "constant", "interpolation", "lookup_enrichment", "cross_recipe"
   - `expression`: The actual datapill formula or expression
   - `human_explanation`: Plain English description of the transformation
3. **Target**: `target_system.target_object.target_field` -- where the data ends up (action input on a create/update/upsert)
4. **Confidence**: "certain" (explicit datapill mapping), "likely" (naming match or inferred from context), "inferred" (best guess based on step structure)

Also identify **unmapped fields**: fields present in trigger/search output schemas that are never referenced by any downstream action input. These may indicate:
- Intentionally excluded fields (privacy, irrelevance)
- Missing mappings (bugs)
- Fields used only for conditions/filtering (not passed to target)

And **cross-recipe lineage**: fields that flow across recipe boundaries via call_recipe parameters, recipe function inputs/outputs, or event topic payloads.
