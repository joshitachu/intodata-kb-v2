You are analyzing a Workato integration project. Your task is to produce a **Cross-Folder Analysis** -- compare and contrast recipe patterns, shared resources, and business logic across folder groups to identify standardization opportunities, deviations, and best practices worth adopting project-wide.

## Workato Context
Workato projects organize recipes into folders (the `group` field in scan data). Folder-based organization typically follows one of these patterns:

- **By department/domain**: `Sales/`, `Finance/`, `HR/`, `Operations/`
- **By integration**: `Salesforce-NetSuite/`, `Jira-Slack/`, `SAP-BigQuery/`
- **By function**: `Sync/`, `Notifications/`, `Reporting/`, `API/`
- **By environment**: `Production/`, `Staging/`, `Development/`
- **Hybrid**: `Sales/Sync/`, `Sales/Notifications/`, `Finance/Reporting/`

Cross-folder analysis reveals:
- **Shared connections**: Which connections are used across multiple folders (shared infrastructure)
- **Callable recipe / recipe function reuse**: Which sub-recipes are called from multiple folders (shared business logic)
- **Event topic pub/sub spanning folders**: Publishers in one folder, subscribers in another (cross-domain integration)
- **Duplicated patterns**: Similar recipe structures in different folders that could be consolidated
- **Inconsistencies**: Different approaches to the same problem (error handling, validation, naming) in different folders

Key Workato cross-folder concepts:
- **RLCM (Recipe Lifecycle Management)**: Packages that export/import recipes, sub-folders, connections, custom connectors, and recipe functions across workspaces/environments. RLCM packages define the deployment unit -- understanding folder boundaries helps identify package candidates.
- **Connection sharing**: Connections are workspace-level resources accessible to all folders. Consistent connection naming per environment enables smooth RLCM deployment.
- **Recipe functions** (post-Dec 2021): Reusable logic units that replace legacy callable recipes. Recipe functions are focused on reusability with simpler design -- they do NOT create API endpoints (use API recipes for that). Understanding whether the project uses recipe functions or legacy callable recipes indicates modernization status.

## What to Extract

1. **Folder inventory**: For each folder group:
   - Recipe count
   - Recipe types (triggers: polling, webhook, API, event topic, scheduled)
   - Connections used (providers)
   - Callable recipes / recipe functions defined vs consumed
   - Event topics published / subscribed
   - Custom adapters used
   - Active vs inactive recipe count

2. **Shared connections across folders**: For each connection:
   - Provider name and connection type
   - Which folders use it
   - Whether connection naming is consistent (same name across folders/environments)
   - Whether a connection is used by only one folder (could be folder-scoped)

3. **Cross-folder recipe reuse**: Map callable recipe / recipe function dependencies:
   - Which recipes are called from multiple folders?
   - What is the call graph (caller folder -> callee folder)?
   - Are recipe functions (modern) or legacy callable recipes used?
   - Are there reuse opportunities (similar logic in multiple folders that could become a shared recipe function)?

4. **Event topic topology**: Map pub/sub relationships across folders:
   - Publishers: which folder publishes to which topics?
   - Subscribers: which folders subscribe to which topics?
   - Cross-domain event flows (e.g., Sales publishes `new_order`, Finance subscribes for invoicing, Warehouse subscribes for fulfillment)
   - Missing subscribers (topics published but no subscribers)
   - Orphaned subscriptions (subscribing to non-existent topics)

5. **Business logic comparison across folders**: Compare how different folders handle:
   - Error handling patterns (monitor/catch coverage, notification channels, retry strategies)
   - Data validation rules (null checks, type validation, format enforcement)
   - Data transformation patterns (cleansing, enrichment, mapping)
   - Naming conventions (recipe names, step aliases, variable names)
   - Trigger patterns (polling intervals, batch sizes, dedup strategies)

6. **Deviation detection**: Where do folders diverge in approach?
   - Same external system accessed differently (different connection, different API pattern)
   - Same business rule implemented differently (different validation logic, different defaults)
   - Inconsistent error handling (one folder uses Slack, another uses email, a third has none)
   - Inconsistent naming (one folder follows a convention, another does not)

7. **Standardization score**: Rate cross-folder consistency (1-10):
   - Connection naming consistency
   - Error handling pattern consistency
   - Naming convention adherence
   - Reuse level (recipe functions, shared recipes)
   - Overall architectural alignment

8. **Best practices by folder**: Which folder has the best implementation in each area?
   - Error handling: most robust monitor/catch coverage?
   - Performance: best use of batch actions, efficient polling?
   - Reusability: most recipe function / callable recipe usage?
   - Data quality: most comprehensive validation?

9. **Refactoring opportunities**: Suggest standardization actions:
   - Duplicated recipes that could become shared recipe functions
   - Inconsistent error handling that should be standardized
   - Connection naming that should follow a convention
   - RLCM package candidates (which folders should be packaged together?)
