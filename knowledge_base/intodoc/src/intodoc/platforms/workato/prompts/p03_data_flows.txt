You are analyzing a Workato integration project. Your task is to produce a **Data Flow Analysis** -- a complete mapping of every data input, transformation, and output for each recipe in this chunk, with human-readable explanations of all field mappings and datapill references.

## Workato Context
In Workato, data flows through recipes via datapill references and field mappings:

- **Triggers (data sources)**: The trigger step (step 0) produces the initial data. Polling triggers (new_record, updated_record) return records from an app. Webhook and API triggers receive data from external HTTP requests. Event topic triggers receive event payloads. The trigger's output schema defines the fields available as datapills to all downstream steps.

- **Datapill references**: Workato's primary data mapping mechanism. Datapills reference output fields from previous steps using the syntax: `#{_('data.step_alias.field_path')}`. The `as` field on each step defines the step alias used in datapill paths. For example, if step 1 has `"as": "salesforce_1"`, then its Account Name field is referenced as `#{_('data.salesforce_1.account_name')}`. Datapills can traverse nested objects using dot notation: `#{_('data.netsuite_1.billing_address.city')}`.

- **Formula methods on datapills**: Datapill references can include Ruby-like transformation methods chained onto the reference:
  - String methods: `.to_s` (convert to string), `.strip` (trim whitespace), `.upcase` / `.downcase` (case), `.gsub(pattern, replacement)` (regex replace), `.split(delimiter)` (split to array), `.truncate(length)` (truncate)
  - Numeric methods: `.to_i` (to integer), `.to_f` (to float), `.round(n)` (round), `.abs` (absolute value)
  - Date methods: `.to_date` (parse to date), `.strftime(format)` (format date), `.beginning_of_day` / `.end_of_day` (day boundaries)
  - Conditional methods: `.presence || default_value` (default if blank), ternary `condition ? true_val : false_val`
  - Null checks: `.present?` (non-null and non-empty), `.blank?` (null or empty)

- **Action input mappings**: Each action step has an `input` object that maps field names to values. Values can be:
  - Static strings/numbers (hardcoded values)
  - Datapill references (`#{_('data.step_alias.field')}`)
  - Complex formulas combining multiple datapills with string interpolation and method chaining
  - Nested objects (for structured inputs like address blocks)
  - Arrays (for list inputs)

- **Action output schemas**: Each action produces output fields that become available as datapills to subsequent steps. The output schema depends on the action type and the target app's object definition.

- **Search and lookup actions**: Actions like `search_records`, `get_record`, and `lookup_table_entry` retrieve data that feeds into downstream steps. They function as data sources within the recipe flow.

- **HTTP request/response mappings**: `send_request` actions (custom HTTP calls) have explicit request body mappings (from datapills to HTTP fields) and response body parsing (from HTTP response to step output fields).

- **Foreach loop data context**: Inside a `foreach` loop, the current item's fields are available as datapills scoped to the loop iteration. The loop variable is typically accessed via the foreach step's alias.

## What to Extract
For each recipe in this chunk:

1. **Data inputs (sources)**: For every trigger and search/get/lookup action, identify:
   - Source system name and type (Salesforce, NetSuite, PostgreSQL, HTTP API, etc.)
   - The connection/provider used
   - Object type, table name, or API endpoint being queried
   - Any filter criteria, SQL query, or search conditions
   - Output schema: list all fields with their data types (if available from the scan data)
   - How this data enters the recipe flow (trigger output, search result, lookup return)

2. **Field mappings and transformations**: For every action step with input mappings:
   - List every input field and its mapping expression
   - **CRITICAL**: For each datapill reference or formula, provide a HUMAN-READABLE explanation. Do not just repeat the expression -- translate it to plain English. Examples:
     - `#{_('data.salesforce_1.account_name')}` -> "Takes the account name from the Salesforce trigger output"
     - `#{_('data.salesforce_1.annual_revenue')}.to_f.round(2)` -> "Takes the annual revenue from Salesforce, converts to decimal, and rounds to 2 decimal places"
     - `#{_('data.netsuite_1.email')}.present? ? #{_('data.netsuite_1.email')} : 'no-email@placeholder.com'` -> "Uses the NetSuite email if available, otherwise defaults to a placeholder email address"
     - `#{_('data.salesforce_1.first_name')} #{_('data.salesforce_1.last_name')}`.strip -> "Combines first and last name from Salesforce with a space, then trims whitespace"
   - Identify which step alias each datapill references (trace back to the source step)
   - Flag any hardcoded values that should be properties or lookup table entries

3. **Data outputs (targets)**: For every create/update/upsert/delete action, identify:
   - Target system name and type
   - The connection/provider used
   - Object type, table name, or API endpoint being written to
   - Write mode: CREATE, UPDATE, UPSERT, DELETE
   - Which fields are written and their source datapill mappings
   - Any match/deduplication keys for upsert operations

4. **HTTP request/response analysis**: For every `send_request` action:
   - HTTP method (GET, POST, PUT, DELETE)
   - URL (including any datapill-based path parameters)
   - Request headers
   - Request body field mappings
   - Response parsing: which response fields are used downstream

5. **Data lineage**: For key fields, trace the path from source trigger through all transformation steps to the final target action. Show how each field value changes along the way.

6. **Cross-recipe data flows**: Identify data that flows between recipes via:
   - call_recipe input/output parameters
   - Event topic payloads (publisher schema -> subscriber trigger)
   - Shared lookup tables or Workato DB tables
   - Shared external system tables (recipe A writes, recipe B reads)
