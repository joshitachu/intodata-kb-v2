You are analyzing a Workato integration project. Your task is to produce an **Expression Catalog** -- a comprehensive index of every datapill formula expression, condition, and transformation in the recipes, with plain-English explanations, complexity scores, and business rule identification.

## Workato Context
Expressions in Workato appear in several places:

### 1. Datapill Formula Expressions (Action Inputs)
These define how fields are mapped and transformed for action step inputs:
- **Direct datapill reference**: `#{_('data.trigger.customer_name')}` or `{{trigger.customer_name}}` -- copies source field as-is
- **Method chain**: `#{_('data.trigger.customer_name')}.strip.upcase` -- applies Ruby-like transformations
- **Ternary conditional**: `#{_('data.trigger.status')}.present? ? #{_('data.trigger.status')} : 'UNKNOWN'`
- **String interpolation**: `"Order: #{_('data.trigger.order_id')} - #{_('data.trigger.customer_name')}"`
- **Arithmetic**: `#{_('data.trigger.quantity')}.to_i * #{_('data.trigger.unit_price')}.to_f`
- **Date operations**: `#{_('data.trigger.created_at')}.to_date.strftime('%Y-%m-%d')`
- **Null coalescing**: `#{_('data.trigger.middle_name')}.presence || ''`

### 2. Condition Expressions (if/elsif blocks)
Conditional branches use field/operator/value triples or complex boolean expressions:
- Field comparisons: `trigger.status == 'Active'`, `trigger.amount > 1000`
- Presence checks: `trigger.email.present?`, `trigger.phone.blank?`
- Pattern matching: `trigger.name.include?('Test')`, `trigger.code.match?(/^[A-Z]{3}$/)`
- Compound conditions: `trigger.status == 'Active' && trigger.amount > 0`

### 3. Stop Message Expressions
WorkatoStop actions include error message expressions that combine datapills:
- `"Invalid order: #{_('data.trigger.order_id')} - amount is #{_('data.trigger.amount')}"`

### 4. TMapEntry Expressions (from parser)
The scan data may include TMapEntry records with structured expression data:
- `table_name` = step alias receiving the data
- `column_name` = destination field name
- `expression` = the datapill formula computing the value

### 5. Lookup Table Key Expressions
Lookup table queries use datapill expressions as search keys:
- `lookup('status_mapping', 'sf_status': #{_('data.trigger.Status')})`

### Ruby Method Reference
Datapills support Ruby-like method chaining:

**String methods**: `.to_s` (convert to string), `.strip` (trim whitespace), `.upcase` / `.downcase` (case conversion), `.gsub(pattern, replacement)` (regex substitution), `.split(delimiter)` (tokenize), `.truncate(length)` (limit length), `.include?(substring)` (contains check), `.start_with?` / `.end_with?` (prefix/suffix check)

**Numeric methods**: `.to_i` (to integer), `.to_f` (to float), `.round(decimals)` (rounding), `.abs` (absolute value), `.ceil` / `.floor` (ceiling/floor)

**Date methods**: `.to_date` (parse to date), `.strftime(format)` (format date as string), `.beginning_of_day` / `.end_of_day` (day boundaries), `.beginning_of_month` / `.end_of_month` (month boundaries), `.ago(duration)` / `.since(duration)` (date arithmetic), `.to_i` (Unix timestamp)

**Conditional methods**: `.present?` (non-null and non-empty), `.blank?` (null or empty), `.presence || default` (null coalescing), ternary `condition ? true_val : false_val`

## Complexity Scoring

Score each expression 1-5:
- **1 (trivial)**: Direct datapill reference (`trigger.field`), constant value (`'US'`, `42`), simple `.present?` check
- **2 (simple)**: Single method call (`.strip`, `.to_i`, `.upcase`), basic null coalescing (`.presence || default`)
- **3 (moderate)**: Chained methods (`.strip.upcase`), ternary with method calls, lookup table key expression, single string interpolation with 2 datapills
- **4 (complex)**: Multi-method chain + interpolation combining 3+ datapills, nested ternaries, arithmetic with type conversions, date arithmetic with formatting
- **5 (very complex)**: Nested conditionals with regex (`.gsub` with patterns), complex multi-line interpolation, expressions referencing 5+ datapills from different steps, recursive formula chains

## Expression Type Classification

Classify each expression:
- `direct_ref`: Direct datapill reference (`trigger.field`, `steps.alias.field`)
- `constant`: Static value (`'US'`, `42`, `true`)
- `method_chain`: Ruby method transformations (`.strip.upcase`, `.to_i.abs`)
- `ternary`: Conditional expression (`field.present? ? a : b`)
- `interpolation`: String building with embedded datapills (`"Order: #{...} - #{...}"`)
- `arithmetic`: Mathematical operations (`quantity * unit_price`)
- `condition`: Boolean expression from if/elsif blocks (`status == 'Active'`)
- `lookup_key`: Expression used as lookup table search key
- `stop_message`: Error message in WorkatoStop action

## Business Rule Flagging

Flag an expression as `is_business_rule: true` when it:
- Encodes a business decision (status code mapping, category classification, routing rules)
- Implements a threshold or cutoff (amount > 10000, date before deadline)
- Contains hardcoded business parameters (tax rates, discount percentages, fiscal year dates)
- Maps values between systems (Salesforce status -> NetSuite status)
- Filters data based on business criteria (exclude test accounts, include only active orders)

Do NOT flag as business rule:
- Technical null handling without business meaning (`.presence || ''`)
- Simple type conversions (`.to_i`, `.to_s`)
- Direct field mappings with no logic
- Standard formatting (`.strip`, `.upcase` for normalization)
