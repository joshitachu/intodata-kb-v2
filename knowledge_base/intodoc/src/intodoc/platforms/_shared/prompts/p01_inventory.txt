You are analyzing an integration project built on a data integration platform. Your task is to produce a **Component Inventory** -- a comprehensive catalog of every job, component, connection, and dependency in this chunk.

## Integration Platform Context
In integration platforms, a "job" (also called a flow, workflow, pipeline, or recipe) is a data integration workflow containing:
- **Components** (nodes/steps): These are the building blocks of a job -- database connectors, transformation steps, file readers/writers, API callers, orchestration triggers, custom code blocks, etc.
- **Connections** (edges/links): Data flow connections that pass rows between components, trigger connections that control execution order (success/failure triggers), and conditional connections that route data based on expressions.
- **Configuration variables**: Environment-specific parameters (PROD, TEST, DEV, Default) that control connection strings, file paths, API endpoints, and other runtime settings.
- **Job orchestration references**: Parent-child job relationships where one job calls or triggers another job, enabling multi-step pipeline execution.

## What to Extract
For each job in the chunk, identify:

1. **All components** with their type, unique name, and purpose
2. **Dependencies**: which jobs call which (orchestration references), which shared metadata connections are used (repository/shared connection references)
3. **Referenced by**: which parent jobs call this job
4. **Orphaned components**: components with no incoming or outgoing connections
5. **Missing references**: references pointing to non-existent metadata, orchestration references to missing jobs

## Output Format
Return a JSON object with this exact structure:
```json
{
  "components": [
    {
      "name": "job_name / component_unique_name",
      "component_type": "DatabaseInput",
      "location": "region/domain/job_name.item",
      "dependencies": ["connection_db_sales", "child_job_name"],
      "referenced_by": ["parent_job_name"],
      "description": "Reads from VW_Sales view in the regional sales database"
    }
  ],
  "dependency_graph_mermaid": "graph TD\n  A[Job1] --> B[Job2]\n  ...",
  "orphaned_components": ["component_name_with_no_connections"],
  "missing_references": ["ref_to_nonexistent_connection"]
}
```

## Instructions

- **Be thorough.** List every component in every job. Do not skip any.
- For each component, identify its category: source (reads data), sink (writes data), transformation (modifies data), orchestration (calls other jobs), control flow (triggers, conditions), or utility (logging, variables, file operations).
- Trace all dependency references -- both explicit (orchestration calls, shared connection references) and implicit (jobs that read from tables written by other jobs).
- Flag any orphaned components that appear to serve no purpose -- these may be leftover from earlier development.
- Flag any missing references that could cause runtime failures.
- Generate a Mermaid dependency graph showing parent-child job relationships and key data flow dependencies.
