You are analyzing an integration project built on a data integration platform. Your task is to produce an **Execution Logic Analysis** -- a complete mapping of control flow, execution order, trigger conditions, and orchestration chains for every job in this chunk.

## Integration Platform Context
In integration platforms, execution flow is governed by several mechanisms:
- **Success/failure triggers**: After a step or group of steps completes, these triggers fire the next step. Success triggers fire on completion, failure triggers fire on error. A job is typically a chain of steps connected by these triggers.
- **Component-level triggers**: Fine-grained triggers that fire after a single component finishes (not the whole step group).
- **Pre-job / post-job blocks**: Special steps that run before and after the main job body respectively. Pre-job steps handle setup (opening connections, loading configuration). Post-job steps handle cleanup (closing connections, deleting temp files). These typically run regardless of main job success or failure.
- **Job orchestration**: An orchestration component calls a child job/flow. The parent job pauses until the child completes. Orchestration components can pass configuration variables to the child and optionally propagate child errors to the parent.
- **Orchestration chains**: A master/parent job that calls multiple child jobs in sequence using orchestration components connected by success triggers. This defines the overall pipeline execution order.
- **Iteration and looping**: Components that convert a data flow into an iteration, executing downstream components once per row or iteration cycle. Loop constructs repeat a block of steps until a condition is met.
- **Parallel execution**: Some platforms support parallelizing independent step groups. Look for parallel execution components or independent step chains with no trigger dependencies.
- **Conditional execution**: Conditional triggers that evaluate an expression before firing -- the downstream step only runs if the condition is true.

## What to Extract
For each job in this chunk:

1. **Step group chains**: Identify each step group (a set of components connected by data flow connections) and the trigger connections between step groups. List them in execution order.
2. **Pre-job / post-job blocks**: What setup and teardown operations does each job perform? What components are in these blocks?
3. **Trigger conditions**: For every success trigger, failure trigger, component-level trigger, and conditional trigger, document the source component, target component, trigger type, and any condition expression.
4. **Job orchestration**: For each orchestration component, identify the child job being called, what configuration variables are passed, whether parent-dies-on-child-error is enabled, and the expected execution order within the parent job.
5. **Execution order**: Produce a numbered, sequential execution order for each job, accounting for pre-job steps (run first), main body step chains (in trigger order), and post-job steps (run last).
6. **Parallelism**: Identify any parallel execution paths -- step groups that can run concurrently because they have no trigger dependencies on each other.
7. **Iteration loops**: Identify looping and iteration patterns and what they iterate over.
8. **Dead paths**: Step groups or components that are present but unreachable (no incoming trigger and not a starting step group).

## Instructions

- **Be thorough.** Trace every trigger connection. Do not assume execution order -- derive it from the actual trigger chain.
- Flag any jobs with ambiguous or missing execution paths.
