You are analyzing an integration project built on a data integration platform. Your task is to produce a **Synthesis Report** -- this is the final analysis pass. You are receiving the consolidated results from ALL prior analysis passes. Your job is to synthesize these results into a comprehensive, actionable documentation package including an executive summary, FAQ, glossary, onboarding guide, and risk dashboard.

## Integration Platform Context
This is a data integration project that moves and transforms data between source systems and target systems. Prior passes have analyzed:
- **Pass 1 (Inventory)**: All jobs, components, connections, dependencies, and the dependency graph
- **Pass 2 (Execution)**: Control flow, execution order, trigger conditions, orchestration chains, mermaid flowcharts
- **Pass 3 (Data Flows)**: Data inputs, transformations with human-readable explanations, data outputs, lineage
- **Pass 4 (Environment)**: Configuration variables across environments, risky differences, hardcoded values, credential handling
- **Pass 5 (External Systems)**: All external systems (databases, file systems, APIs, cloud services), connection details, topology
- **Pass 6 (Error Handling)**: Error handling ratings per job, silent failure risks, missing error handlers, reject flow gaps
- **Pass 7 (State)**: Temporary files, staging tables, global variables, cleanup gaps, re-run safety, side effects
- **Pass 8 (Custom Code)**: Custom code analysis, hidden business rules in code, security findings
- **Pass 9 (Business Logic)**: Business domains, extracted business rules, business parameters, impact analysis, rule conflicts

You have access to ALL of these results. Your task is to cross-reference them and produce a unified synthesis.

## What to Produce

### 1. Executive Summary
Write a 1-2 paragraph executive summary suitable for a CTO or VP of Engineering. Cover:
- What this integration project does at a high level
- How many jobs, external systems, and data flows exist
- The overall health/quality assessment (good, needs improvement, at risk)
- Top 3-5 risks that need immediate attention
- Key recommendation for the team

### 2. Architecture Overview
Produce a concise description of the overall system architecture:
- How many layers exist (RAW, CLEAN, PUBLISH, etc.) and what each does
- The master orchestration pattern (how jobs are chained)
- Which external systems are sources vs. targets
- A master Mermaid architecture diagram showing the end-to-end flow

### 3. Risk Dashboard
Consolidate ALL risks from all passes into a single prioritized dashboard. For each risk:
- Unique risk ID
- Category (error_handling, security, environment, data_quality, performance, maintainability, reliability)
- Severity: CRITICAL, HIGH, MEDIUM, LOW
- Description in plain English
- Affected jobs/components
- Recommended remediation
- Estimated effort to fix (hours/days/weeks)

Sort by severity (CRITICAL first), then by number of affected jobs.

### 4. FAQ (20+ items)
Generate at least 20 frequently asked questions that a new team member, auditor, or stakeholder might ask, with detailed answers based on the analysis. Cover these categories:
- **General**: "What does this project do?", "How many jobs are there?", "What systems does it connect to?"
- **Operations**: "How do I run these jobs?", "What happens if a job fails?", "Can I safely re-run a job?", "What is the execution order?"
- **Data**: "Where does the data come from?", "What transformations are applied?", "How is data quality ensured?", "What business rules are applied?"
- **Security**: "How are credentials managed?", "Is there any data masking?", "What are the security risks?"
- **Maintenance**: "How do I add a new data source?", "What happens when a source schema changes?", "Where is business logic defined?"
- **Troubleshooting**: "How do I debug a failed job?", "Where are error logs?", "What are common failure modes?"

### 5. Glossary
Compile a glossary of all domain-specific terms, abbreviations, and codes found across all passes:
- Job name prefixes and their meanings (region codes, domain codes, layer codes)
- Status codes and their business meanings
- System abbreviations
- Platform-specific technical terms that non-specialists need to understand
- Business terms found in column names, table names, and documentation

### 6. Onboarding Guide for New Developers
Write a structured onboarding guide that a new developer joining the team can follow:
- Prerequisites (platform version, runtime environment, access to systems)
- How the project is organized (folder structure, naming conventions)
- How to set up local development (which environment profile to use, how to avoid hitting production)
- How to understand a specific job (which files to read, what to look for)
- How to make changes safely (testing strategy, deployment process)
- Common pitfalls to avoid (based on the risks identified)
- Key contacts or escalation paths (if identifiable from the project)

### 7. Cross-Cutting Concerns
Identify patterns and issues that span multiple passes:
- Jobs that appear in multiple risk categories (compound risk)
- Business rules that are implemented inconsistently across jobs
- External systems that are single points of failure
- Data flows where a failure in one job cascades to many downstream jobs
- Patterns that should be standardized (e.g., all jobs should have centralized error logging, all connections should use shared metadata)

### 8. Recommendations Roadmap
Prioritize all recommendations into a phased roadmap:
- **Immediate (this sprint)**: Critical security and data-loss risks
- **Short-term (this quarter)**: Error handling improvements, environment isolation fixes
- **Medium-term (next quarter)**: Refactoring duplicated logic, standardizing patterns
- **Long-term (backlog)**: Architecture improvements, monitoring enhancements
