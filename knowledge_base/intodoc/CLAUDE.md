# intodoc -- Integration Documentation Generator

> **Note:** This file describes the intodoc CLI scanner. For the MCP-based documentation
> agent workflow (which is the current primary doc generation method), see `vaxxinova/CLAUDE.md`.

## What is this?
A Python CLI tool that scans integration codebases (Talend, MuleSoft, dbt, etc.) and produces structured scan data. Originally included LLM-based analysis and Jinja2 doc generation; documentation is now generated by the Claude Code agent via MCP (see `vaxxinova/CLAUDE.md`).

## Quick Start
```bash
cd intodoc
pip install -e ".[dev]"
intodoc scan ../vaxxinova-talend --platform talend --output-dir ../intodoc-output
```

## Key Architecture
- **Platform-explicit**: user declares `--platform talend|workato|generic` -- loads platform-specific parser, prompts, best practices
- **Platform plugins**: `src/intodoc/platforms/<name>/` -- each is self-contained (Talend, Workato, Generic)
- **Inheritance**: `PlatformPlugin -> GenericPlugin -> WorkatoPlugin`, `BaseDistiller -> TalendDistiller/WorkatoDistiller`
- **Prompt resolution**: Platform-specific prompts override `_shared/prompts/` fallback
- **Dual doc generation**:
  - **Primary (MCP agent)**: Claude Code reads prompts + fetches chunks via MCP, writes .md docs directly
  - **Legacy (CLI)**: 21-pass LLM analysis via LiteLLM API + 32 Jinja2 templates
- **Universal IR**: `intodoc normalize` converts ScanResult to platform-agnostic NormalizedProject

## Project Layout
- `src/intodoc/cli.py` -- Click CLI entry point (scan, normalize, analyze, generate, export, run)
- `src/intodoc/config.py` -- Pydantic Settings configuration
- `src/intodoc/models.py` -- ALL shared Pydantic data models (30+)
- `src/intodoc/ir/` -- Universal Intermediate Representation (models, expression_parser, normalizer, dag, persistence, pseudocode, validator, type_inferrer, llm_enrichment)
- `src/intodoc/scanner/` -- file walking, git analysis, credential filtering
- `src/intodoc/platforms/` -- platform plugins (talend/, workato/, generic/, _shared/)
- `src/intodoc/platforms/base_distiller.py` -- shared chunking logic for all platforms
- `src/intodoc/chunker/` -- group jobs into LLM-sized chunks
- `src/intodoc/analyzer/` -- LLM client, passes (21), cost tracking (legacy CLI path)
- `src/intodoc/generator/` -- Jinja2 markdown rendering, 32 templates (legacy CLI path)
- `src/intodoc/exporter/` -- PDF and Qdrant export
- `reference-docs/` -- 25 example .md files (format/structure spec for doc agents)

## Known Pitfalls
- **Windows encoding**: Unicode chars (em-dashes, arrows) break on cp1252 -- use ASCII in CLI text
- **Token bloat**: tMap distiller MUST strip noise BEFORE chunking -- field_type filtering is critical
- **ENDPOINT preservation**: Don't strip URL-related params -- REST/OData endpoints are semantically important
- **Connection matching**: Use component `REPOSITORY_PROPERTY_TYPE` refs, NOT region-name matching
- **hatchling**: Use hatchling build system, NOT setuptools -- pyproject.toml is configured for it
- **Budget**: Default $5 limit for legacy CLI analyzer -- 18 passes on 9 chunks can exceed this with larger models
