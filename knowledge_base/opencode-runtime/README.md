# OpenCode experiment task runtime

This image is the isolated runtime boundary for the additive agentic
documentation experiment. It pins OpenCode `1.18.4`, starts in `--pure` mode,
and denies every tool in its base configuration.

It is deliberately a **disposable, one-task runtime**, not a shared mutable
OpenCode server. The launcher must provide:

- a random Basic-auth password;
- a short-lived, task-scoped Nexus MCP token;
- a complete `OPENCODE_CONFIG_CONTENT` document generated by the trusted Nexus
  permission compiler;
- only the provider credential required by the selected provider/model route.

The generated configuration may enable only the exact Nexus MCP tools declared
by the task. Its remote MCP authorization header references
`{env:NEXUS_EXPERIMENT_TASK_TOKEN}`; it must never contain the token value.
Provider credentials and server passwords must likewise never be written into a
configuration, receipt, prompt, event, or artifact.

The production launcher should apply the controls illustrated in
`compose.service.example.yml`: no repository or output mounts, an internal
network only, a read-only root filesystem, all Linux capabilities dropped,
`no-new-privileges`, and temporary writable state. The task obtains evidence
and writes its one declared candidate output exclusively through the scoped
Nexus MCP server.

Before prompting a model, Nexus must verify the effective runtime:

1. `/global/health` reports exactly `1.18.4`;
2. the requested provider/model is connected and eligible;
3. the Nexus MCP server is connected;
4. the effective agent has no built-in shell, web, or external-directory authority;
5. single-agent tasks have no subagent authority; the original orchestrated
   benchmark may invoke only the configured `nexus-doc-*` subagents at depth
   one; the Grounded candidate never grants Task authority because Nexus
   dispatches its recipe-declared roles directly;
6. only the task's exact file or MCP tools are enabled.

The recommended Grounded candidate is a Nexus-owned staged execution. Nexus
compiles a provider-neutral recipe pack, creates a physically separate
workspace for each evidence, analysis, writing, and review role, and copies
only that role's bounded input packet into it. Raw frozen source content is
assigned only to evidence roles. A downstream role receives an upstream
artifact only after Nexus has checked exact ownership, non-empty content, JSON
shape where applicable, and secret safety. Failed artifacts remain in their
isolated role workspace and are never copied downstream.

Every role uses the provider/model selected in the normal Generate Docs UI.
Nexus dispatches independent ready roles up to the pack concurrency limit and
allows only the pack's bounded repair count. The model may read, search, and
write inside its contained role workspace, but cannot use OpenCode Task
dispatch. Finalization depends on accepted files and Nexus-owned state rather
than a parent agent's final message.

For current IntoDoc runs, Nexus also supplies an immutable `FACT_LEDGER.json`
compiled deterministically from the frozen scanner snapshot. Protected counts
and relationships are checked locally after generation, and unresolved fact
mismatches reject the candidate. Recipe-mode packs use the same staged runner
with generic frozen source items (for example text, JSON, CSV, or runtime
exports); the quick Generate Docs entry point currently freezes the approved
IntoDoc source set, while other source adapters compose their inputs before
dispatch.

The legacy, single-agent, and original OpenCode-orchestrated modes remain
separate and unchanged.

Any failed preflight aborts the task before provider traffic. The container is
destroyed after completion or cancellation; task tokens expire independently.
