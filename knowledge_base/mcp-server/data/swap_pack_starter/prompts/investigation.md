Focus investigation on evidence that will make the final documentation useful
to engineers and operators.

Capture concrete names and relationships:

- canonical units, jobs, recipes, services, workflows, or modules
- inbound and outbound systems
- files, tables, entities, messages, APIs, schedules, and runtime triggers
- transformations, branching rules, filters, mappings, validations, and error
  handling
- config keys and connection names after credential redaction

If evidence is missing, say what is missing and which unit is affected. Do not
guess values, endpoints, tables, credentials, schedules, owners, or SLAs.
